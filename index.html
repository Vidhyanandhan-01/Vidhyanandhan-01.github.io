Research

Jun 2026 – Present
Speculative Prefetch Pollution: Confidence-Gated Prefetch Dispatch in Out-of-Order Cores
Advised by Prof. Karu Sankaralingam — Principal Research Scientist, NVIDIA · Vertical Research Group, UW–Madison
ChampSim (C++) ChampSim-wp gem5 O3CPU SPEC CPU Branch Prediction

Modern OOO cores speculate down predicted branch paths, and software prefetchers (Magellan-style long-distance prefetchers) dispatch memory requests during that speculation — when the branch mispredicts, those requests still reach the memory system before the pipeline squashes them, polluting the cache with useless data ("speculative prefetch pollution"). The project combines Magellan's long-distance prefetch throttling with CHESS-style per-branch dynamic confidence to gate dispatch before pollution occurs, rather than after.

— Validated the core premise directly on ChampSim-wp (Princeton's wrong-path-aware ChampSim): 62.9–66.8% of wrong-path loads issue to the memory system before being caught, and on a tailbench_xapian datacenter trace, all 694 wrong-path-triggered prefetches requested at L2C were successfully issued into the queue
— Found pollution is diffuse, not concentrated — 348 distinct triggering PCs, with the single hottest PC accounting for only 4.8% of total wrong-path prefetches
— Oracle (perfect) gating removes ~1.28% of L2C prefetch traffic on tested workloads, with 5.6% of suppressed prefetches (39) later shown to have been useful — quantifying the real ceiling and cost of gating
— Workload variance: SPEC traces (mcf, xalancbmk, gcc, perlbench) show concentrated wrong-path waste vs. genuinely diffuse patterns in cloud/datacenter code
— Showed program-wide branch accuracy (97.17%, 2.46 MPKI) under-predicts wrong-path rate 5×, isolating a hard-to-predict (H2P) gating branch — per-branch, not program-average, confidence is the right signal
— Calibrated an analytical model to a published DRAM-bandwidth ceiling (Magellan, ISCA'25), correcting an initial 4×-high estimate down to 1.62% residual error
— Currently implementing Phase 5: a graduated delay/downgrade/suppress prefetch gate driven by per-branch reconvergence confidence, moving from ChampSim's trace-driven model to gem5's execution-driven O3CPU for realistic wrong-path fetch
